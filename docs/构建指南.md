# 构建指南

从零构建出 `maa-web.fpk`。整个过程分两段：**先做 Docker 镜像**，**再打 fpk 包**。

> 💡 镜像构建比较吃资源（1.15GB 镜像、解压 400MB+ 的官方包），
> 建议丢到另一台有 Docker 的机器上做，再把产物拷回 NAS。**不要**在你日常用的飞牛上跑构建。

---

## 0. 前置条件

| 依赖 | 说明 |
|---|---|
| Docker | 构建机需安装，版本不限（实测 Docker 29.x 可用） |
| `fnpack` | 飞牛官方打包工具，只在打 fpk 那一步需要 |
| `python3` + Pillow | 仅当你要重新生成图标 |
| 磁盘 | 至少 6GB 空闲 |

`fnpack` 下载（1.2.3，linux-amd64）：

```bash
curl -fL -o fnpack https://static2.fnnas.com/fnpack/fnpack-1.2.3-linux-amd64
chmod +x fnpack && sudo mv fnpack /usr/local/bin/
fnpack --version
```

## 1. 准备两个上游产物

### 1.1 MAA 官方 Linux 版

从 [MAA Releases](https://github.com/MaaAssistantArknights/MaaAssistantArknights/releases) 下载 **Linux x86_64** 包，
重命名为 `maa-linux.tar.gz`。

> ⚠️ 官方包要求 **glibc ≥ 2.38**，所以下面的基础镜像必须是 Ubuntu 24.04（glibc 2.39）或更新。
> 本项目验证过的核心版本：**MAA v6.17.5**。

```bash
# 校验完整性
gzip -t maa-linux.tar.gz && echo "tarball OK"

# 看一眼版本
tar -tzf maa-linux.tar.gz | head
```

### 1.2 MAA-WEB-CONTROL 源码

从 [MAA-WEB-CONTROL](https://github.com/KlN-4096/MAA-WEB-CONTROL) 取源码。
目录名要保持 `MAA-WEB-CONTROL-master/`，`deploy/build.sh` 依赖它。

```bash
# 方式一：git clone 后改名
git clone https://github.com/KlN-4096/MAA-WEB-CONTROL.git
mv MAA-WEB-CONTROL MAA-WEB-CONTROL-master

# 方式二：下载 zip 解压 —— 解压出来的目录名天然就是 MAA-WEB-CONTROL-master/
```

> 本项目验证过的版本：**v0.2.0**。

## 2. 构建 Docker 镜像

`deploy/Dockerfile` 是三段式：装运行期依赖 → 铺 MAA 官方包 → 铺 Web 前端。
**注意 `COPY redroid-proxy/docker /usr/local/bin/docker` 这一层**，它是 redroid 状态查询的关键。

```bash
# 把仓库里的 deploy/ 与 redroid-proxy/ 放到一起
mkdir -p ~/maa-build && cd ~/maa-build
cp -r /path/to/MAA-FnOS/deploy .
cp -r /path/to/MAA-FnOS/redroid-proxy .
cp /path/to/maa-linux.tar.gz .
cp -r /path/to/MAA-WEB-CONTROL-master .

# 组装构建上下文（Dockerfile 需要的都在同一层）
#   注意：Dockerfile 里 COPY 的是 redroid-proxy/docker，所以这一层必须在上下文根
docker build -t maa-web-control:local \
  --build-arg MAA_TARBALL=maa-linux.tar.gz .
```

或者直接用仓库里的脚本（**记得先按自己的目录改 `WORK` 变量**）：

```bash
bash deploy/build.sh
```

构建成功后确认：

```bash
docker images maa-web-control:local
# REPOSITORY           TAG     IMAGE ID       SIZE
# maa-web-control      local   5c88742ddffc   1.15GB
```

### 2.1 冒烟测试（推荐，省得打完整包才发现问题）

```bash
# 起一个临时容器
docker run -d --name maa-smoke --restart no -p 18000:8000 \
  -e MAA_ADAPTER=official -e MAA_CORE_DIR=/opt/maa \
  -e MAA_WEB_HOST=0.0.0.0 -e MAA_WEB_PORT=8000 -e TZ=Asia/Shanghai \
  maa-web-control:local

sleep 15
curl -s http://127.0.0.1:18000/api/version
# 期望：{"web_version":"0.2.0","core_version":"v6.17.5", ...}

# 验证 MaaCore 的 Python 绑定能加载
docker exec maa-smoke /app/.venv/bin/python /app/../probe_maa.py 2>/dev/null || \
  docker exec maa-smoke /app/.venv/bin/python -c \
  "import sys; sys.path.insert(0,'/opt/maa/Python'); from asst.asst import Asst; Asst.load('/opt/maa'); print('core:', Asst.get_version())"

docker rm -f maa-smoke
```

## 3. 导出并压缩镜像

fpk 要内置离线镜像，所以得把镜像导成 tar 再压：

```bash
docker save maa-web-control:local | gzip -9 > maa-image.tar.gz

ls -lh maa-image.tar.gz
# 约 585MB（未压缩约 1.15GB，gzip 压掉一半）
```

> 关于压缩级别：`-9` 最省体积但慢；`-6` 是速度/体积平衡点，差别约 1~2%。
> **每次重建镜像后 docker image ID 都会变**，这正是 1.0.2 引入「镜像指纹比对」的原因。

---

## 4. 组装并打包 fpk

```bash
cd fnos-app
cp ../maa-image.tar.gz app/
ls -la app/          # 应看到 maa-image.tar.gz

fnpack build
ls -la *.fpk         # 约 613MB
```

`fnpack` 会强制校验这几样，缺一样都会报错：

- `manifest` 里的 `desktop_uidir`（本项目为 `ui`）与 `app/ui/` 目录必须同时存在
- 包根必须有 `ICON.PNG`（64x64）与 `ICON_256.PNG`（256x256）
- `manifest` 必填字段：`appname` / `version` / `display_name` / `platform` / `source` /
  `maintainer` / `distributor` / `desktop_uidir` / `desktop_applaunchname` / `ctl_stop` / `os_min_version`

仓库里的 `assemble.sh` 是给「从官方骨架复制 + 覆盖定制文件」的场景用的，按需修改。

## 5. 安装到飞牛

```bash
# 传到 NAS（大文件走内网 rsync 更快）
rsync -avP --partial --inplace maa-web.fpk <user>@<NAS_IP>:/home/<user>/

# NAS 上安装
sudo appcenter-cli install-fpk --volume 1 /home/<user>/maa-web.fpk

# 启动并发起状态检查
sudo appcenter-cli start maa-web
sudo appcenter-cli status maa-web      # 返回 0 = running
```

## 6. 发布前验收清单

```bash
grep ^version /vol1/@appcenter/maa-web/manifest                       # 版本号已递增
sudo appcenter-cli status maa-web                                     # running
sudo docker ps --filter name=maa-web                                 # Up + 0.0.0.0:18000->8000
sudo docker inspect maa-web --format '{{.HostConfig.RestartPolicy.Name}}'
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:18000/      # 200
ls /vol1/@appcenter/maa-web/ui/images/ | wc -l                        # 12（图标齐全）
sudo cat /vol1/@appcenter/maa-web/maa-image.id                        # 指纹 == docker image inspect --format '{{.Id}}'
sudo docker images -f dangling=true                                   # 无遗留悬空镜像
ps -eo pid,etime,cmd | grep redroid_status_proxy | grep -v grep       # 只有应用起的那一个
grep -n 'CONTAINER=' /vol1/@appcenter/maa-web/cmd/main                # 容器名符合预期
```

## 常见构建问题

| 现象 | 原因 / 处理 |
|---|---|
| `maa: /lib/x86_64-linux-gnu/libc.so.6: version 'GLIBC_2.38' not found` | 基础镜像太老，必须用 `ubuntu:24.04` |
| `fnpack build` 报缺 `ICON.PNG` | 包根必须有大写 `ICON.PNG` 和 `ICON_256.PNG` |
| `fnpack build` 报 `desktop_uidir` 目录不存在 | `manifest` 声明了 `desktop_uidir = ui` 就必须有 `app/ui/` |
| 装完后打开是空白页 | 容器没起来。看 `/vol1/@appdata/maa-web/info.log` |
| 升级后跑的还是老版本 | 镜像没重新导入，看 CHANGELOG 里 1.0.2 的说明 |
